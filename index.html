why a tide

A tide comes in whether or not you asked.

Search APIs fetch when your agent calls, then bill you for the call. A tide is continuous, scheduled, and driven from outside. That is the difference.

continuous

Current before the question

TIDED refreshes each module on its own schedule, so the answer is already on disk when your agent asks. No cold fetch, no waiting on a crawl.

owned

Your machine, your data, flat price

The engine runs locally and the data stays local. You pay a flat rate for the keeper, never per query, never per token. Open source engine.

modules

Pick what stays fresh

A module is a source, a schedule, and a shape. Use ours, or make your own in a minute. Share one with your team.

how it works

Three steps, then forget it is there.

Install and add a module

One command. Add a site, a folder, a feed, or a module someone else published.

$ brew install tided
$ tided add https://oakfall.app
added · my website · every 6 h · 212 pages

TIDED keeps it current

The daemon fetches on schedule, keeps what changed, and marks each module fresh or stale. Fetching is polite and isolated from your data.

$ tided status
my website         fresh   4 min ago
product docs       fresh   4 min ago
competitors        stale   3 d

Your agent reads it over MCP

Point Claude Code, Cursor, Codex, or a local model at the local server. Exact, bounded reads. No ranking black box.

{ "mcpServers": {
    "tided": { "command": "tided", "args": ["mcp"] }
} }
